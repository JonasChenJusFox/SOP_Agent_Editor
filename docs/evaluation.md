# 审稿评估与校准

这套评估检验三件事。审稿系统是否更容易放过同一模型写的稿件，能否准确发现有依据的问题，以及经人工批准的修改是否引入了新的事实错误或损害了作者声音。实验按初稿、审稿发现和修改后三个层次保留结果，便于定位改进来自哪个环节。

## 1. 构建可盲评的标注集

用合成稿和经作者许可的去标识化样本起步。优先覆盖美国研究生 SOP 的动机、项目叙述和学校匹配，再扩展至个人陈述或其他申请文书。每个案例同时保存学校要求、作者明确偏好、证据摘录、初稿及其来源版本。写稿模型身份单独记录，仅在分析时与评审结果关联。

| 样本 | 构建方式 | 检验内容 |
| --- | --- | --- |
| 真实问题稿 | 对同一底稿制作单处改动变体，或标注作者许可稿中的实际问题 | 把团队成果写成个人成果，无依据的数字，缺少申请题目要求的内容，项目匹配论证跳步 |
| 对应干净稿 | 保留同一上下文，修复注入的问题，人工确认被测试位置及类别 | 精确验证误报，检测审稿人对可接受句式、保留措辞和已有证据的误判 |
| 证据不充分稿 | 模拟缺失、互相矛盾、过期或范围不同的来源 | 是否正确区分「可确认」「需核实」「有直接反证」，是否会把缺证据本身当作事实错误 |
| 合理风格变体 | 保留事实与要求，替换叙述顺序、简历式具体细节或不同正式程度的句式 | 是否尊重作者偏好，是否把可选润色升格成必须修改 |
| 修改回归稿 | 提供对同一问题的正确修复、过度改写和引入新错误的版本 | 能否识别修复效果，并保护原有事实、术语、角色和受保护原文 |

例如，用虚构的餐厅搜索项目测试「实现界面并参与排序」与「独立设计排序系统，带来 30% 的提升」的归因差异。证据包只证明前一项时，后一项应触发核实。若证据明确记录排序由团队共同开发，独立设计的表述可标为有直接反证。数字的判断取决于证据包里是否有对应指标和实验条件。

每条金标准发现记录 `case_id`、文档版本、原文范围或缺失要求编号、问题类别、严重度、证据编号和判定理由。对事实另外记录来源日期与支撑范围。对受保护句和完成度已满足的要求记录明确的负例。缺失内容用题目要求编号定位，避免要求评审引用不存在的原句。预先写明可接受的同义描述及严重度边界。

两名人工标注员独立读稿并标注，双方均看不到写稿来源、模型输出及另一名标注员的判断。先记录原始一致度，再由第三人裁决分歧。保留真正有争议的风格意见，用于单独分析分歧；确认事实、保留措辞和硬性要求的案例进入主指标。系统发现人工漏标的问题时，盲审该问题并记录为待补充标注，冻结的测试结果仍以当次标注版本为准，增补在下一版数据集中统一重跑。

按作者、草稿家族和项目归组拆分开发集、校准集和测试集。同一底稿的修复、改写、故障注入和不同模型生成稿分到同一组。开发集用于改提示词和规则，校准集用于确定置信度区间和裁决阈值，测试集在冻结配置后运行。当前申请季的学校要求、字数限制与项目名称按发布日期固化到评估包。若要测量对新学校的泛化，可单独留出学校组。

## 2. 测量同模型自评效应

以模型 A 和 B 起步。将同一批申请题目、人物事实、写作偏好和证据包分别交给 A、B 写初稿，并为每个稿件建立独立人工标注。每份稿件都由 A 和 B 以相同角色、提示版本和可见证据各审一次。取消写稿者标签，随机化调用顺序，使用各自的新会话。增加人工原创稿作为参照，观察 A、B 对这组稿件的普通误差。写稿和审稿均记录实际模型版本、配置、调用失败及拒绝。对少量样本重复运行，估计输出波动。

| 同一实验内的对照 | 主要比较 |
| --- | --- |
| A 写 A 审，与 A 写 B 审 | 在同一 A 稿件上比较漏检、误报及严重度 |
| B 写 B 审，与 B 写 A 审 | 反向交叉对照，检验现象是否集中在某个模型 |
| 人工写 A 审，与人工写 B 审 | 描述两种评审在人工稿上的普通偏差和基本能力 |
| 两种配置在同一预标注错误变体上审稿 | 控制错误类型和展示难度，检查自然稿结果能否复现 |

对每份稿计算「同模型审稿的严重问题漏检率减去跨模型审稿的漏检率」，按写稿模型分别报告差值，再等权合并两种写稿模型。正差值对应同模型在该指标上更宽松。同步测量严重度低估和对干净点位的误报差值，避免把漏检变少所伴随的泛化误报当作质量提高。置信区间按作者或草稿家族整组重抽样，避免把同一底稿的多条发现、重复调用或四个角色当作独立样本。样本量小或区间较宽时，标为证据不足。结果仅适用于对应模型版本、稿件类型和任务设置。若后续比较「是否知道稿件由自己写」，另作随机显示归属标签的实验，独立报告该效果。

四个 Reviewer 各有自己的职责，可能共同漏掉同一个事实，也可能重复报告同一个问题。每次评估分别记下可合并的发现、同一负例上的共同误报和同一正例上的共同漏检。用相同稿件比较单模型单角色、同模型四角色、多个模型四角色和加入裁决的组合。规划时给出等预算比较和实际运行成本两组结果，避免单纯增加调用次数影响结论。

## 3. 指标与打分口径

在角色内部及报告层分别匹配金标准。匹配条件是同一文档版本、原文范围或要求编号、问题类别，以及指向同一实质问题。每条报告发现与每条金标准最多匹配一次。发现事实风险却给出不成立的因果理由时应人工复核，单列「正确定位但理由无效」。同一问题的重复报告另计重复率，并在最终报告的质量评分前按规则合并。

| 指标 | 计算与记录 |
| --- | --- |
| 发现准确率 `precision` | 匹配有效发现数 ÷ 去重后可评审发现数。未匹配的警报经盲审后区分无效和金标准遗漏，两类数值一起报告，保留冻结口径 |
| 发现召回率 `recall` | 检出的金标准问题数 ÷ 金标准问题总数。按严重度、角色、事实类别分别报告 |
| 点位误报率 `FPR` | 被误标为有问题的预先标注负例点位数 ÷ 已评审的负例点位总数，点位是特定范围与类别的组合 |
| 干净稿误报率 | 至少收到一项无效警报的干净稿件数 ÷ 评估中的干净稿件总数 |
| 严重问题漏检率 | 未检出的严重金标准问题数 ÷ 严重金标准问题总数。另报降级比例及「理由无效」情况 |
| 事实判断质量 | 对有来源支撑、有直接反证、需核实三类分别报告数目与混淆情况，重点追踪对需核实内容的错误确认 |
| 审稿可靠性 | 无效原文锚点率、输出校验失败率、超时率、文档覆盖率。预期四角色的成功覆盖率单列 |
| 修改质量 | 修复比例、引入未经证实主张的次数、受保护原文违规次数、硬性要求回归数及作者对措辞的人工接受率 |
| 成本 | 每篇稿件的调用数、延迟、人工审阅时间及每项有效发现的成本 |

每项比例同时报告计数和分母。分母为零记为不可计算，调用失败另计可用性，并为严重问题召回同时给出成功审稿子集和全量样本结果。`1 − precision` 衡量已发出警报里有多少无效，`FPR` 衡量已知无问题点位被误报的概率。对数值置信度在校准集上检查其与人工判定相符的频率，并在测试集上报告 Brier score 和各置信度分箱的实测准确率。分箱时展示样本数，样本不足的类别保留人工核实。人类接受率单独观察，避免把「作者没有采用一条有效建议」记成检测错误。

## 4. 分阶段验收

以下样本规模和质量门槛是启动建议。试点完成后，依据标注一致度、实际错误分布和人工审阅成本确定发布阈值，并在冻结测试前登记。

| 阶段 | 执行方式 | 建议验收条件 |
| --- | --- | --- |
| MVP | 使用 12–20 份合成文档或变体，手工验收统一格式、原文锚点、审稿聚合和人工批准边界。离线固定响应检验流程，若接入模型，另记录真实审稿表现 | 所有回归用例通过。错误锚点和未经批准的修改均无法应用。固定输入可复现报告。每份报告能追溯到其原稿版本与来源审稿人 |
| Version 2 | 增至 30–50 个各自独立的草稿家族开展试点，覆盖同段分歧、事实冲突和修改回归。报告中保留证据链接及人类决策 | 干净负例点位 `FPR` 启动目标 ≤ 10%，严重问题召回目标 ≥ 90%。高风险固定回归用例全部通过。对报告质量门槛同时给出样本量与区间 |
| Version 3 | 若试点的波动和样本分布支持，准备至少 100 个草稿家族用于跨模型评估和独立留出。对弱势类别补充足够样本，进行同稿配对比较及多轮回归 | 相对现有基线，严重漏检或误报达到预先登记的最小可接受改进，另一项维持允许差值以内。高风险固定回归全部通过。依据实测方差决定是否需要扩大样本 |

## 5. 多轮回归与停止规则

每次修改以经批准的操作和固定原稿版本为输入。先检查修改目标是否解决，再对人物、角色归因、结果数字、学校要求及受保护段落做回归检查。用独立审稿调用重审改稿，先独立找出新增问题，再读上一轮的未解事项。保存修改前后的问题锚点、证据状态和人工决定，便于复查范围移动后的同一问题。

试点默认最多自动生成三轮审查报告，实际修改每轮由作者审批。当硬性要求通过、已确认的高优先级问题关闭、其余问题有明确的人工处理决定时结束。若连续两轮没有新增有效的高优先级发现，或者出现反复改回、证据缺失、输入版本已变，则暂停并交给作者决策。作者也可随时拒绝某项建议并记录原因。任何新增事实或受保护原文违规在交付前都要重新处理。人工反馈进入经许可的开发或校准样本，保留模型和规则版本，冻结测试集用于衡量更新效果。
